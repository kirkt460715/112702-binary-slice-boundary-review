# 设备维护记录读取器的缓冲区边界审计

节点模型仅包含声明的区间、单位及检查引用，无固件、输入字节或运行器。 资料均为本地合成记录。

以 Python 3.11.2 运行，无第三方依赖。`records/` 中的 `layouts`、`reads`、`releases` 对应独立来源。每份材料是 JSON 对象数组，`id` 在同一来源内唯一。报告和观察的时间以各原始记录给出的字段为准。

```sh
python3 -m unittest -v
python3 records_view.py
python3 records_audit.py --summary
```

资料入口列出来源、记录标识及条数。通过 `--source` 指定来源，`--offset` 和 `--limit` 限定读取的位置与数量。`--records` 可指定同样结构的其他资料目录。

## 静态边界审计

`records_audit.py` 只做本地静态核对：不连接设备、不生成测试报文，也不输出任何具体触发字节。报告使用合成的节点编号（`C*` 检查、`R*` 读取、发布记录 `id`）、适用条件和应验证的安全边界表达，并把每个布局拆成“可证明的范围”与“未证明的范围”。默认输出 JSON，`--summary` 输出便于交接的文本；退出码 `0` 表示全部核验通过，`2` 表示仍有待修/待验证项。

判定不依赖“存在长度比较”这一表象，以下情况都会单独记为未覆盖或缺少依据：

- 检查的 `bounds` 是 `whole-frame`，而读取的是子段：整段可读不能替代子段界限。
- 读取的 `length_unit` 与检查的 `offset_unit` 不一致或缺失：比较的变量与单位必须一致。
- `proof` 未显式声明为 `complete`：检查存在不等于覆盖全部后续读取。
- 检查的 `present_in` 不含读取经过的功能组合：该变体没有边界检查。
- 布局只给出 `public_max_bytes`（整段上限）或只声明外层缓冲：不替代逐子段上限。
- 缺少 `path_entries`、`version`、`activated`、`normal_layouts`、`normal_read_results`：分别指出缺少的调用关系、运行版本或发布依据，并标注由版本反推的变体。

评审可把更正后的语句摘要按同样目录结构放入新目录，用 `--records 目录` 重新核对哪些约束已经保护各读取路径；只有检查在场、单位一致、子段界限明确、proof 完整、构建实际启用、且有效布局的正常读取结果已记录时，对应路径才转为 `supported`。报告中 `handoff` 列出按下一位维护人可观察路径归并的剩余待修/待验证项。
